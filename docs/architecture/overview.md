# Обзор архитектуры

## Контекст
Chronocaust_Dev — это проект на Unity **6** (версия редактора в `ProjectSettings/ProjectVersion.txt`, на момент аудита: `6000.4.5f1`), сфокусированный на 2D псевдо-изометрическом геймплее. Рантайм-логика использует кастомную ECS-реализацию в `Assets/Scripts/ECS`, при этом сцены, объекты и жизненный цикл Unity остаются основной платформой.

Связанные документы: [Структура проекта](project-structure.md), [Цикл выполнения](../flows/runtime-loop.md), [Конфигурация](../config/configuration.md).

## Стиль архитектуры
Кодовая база сейчас использует **гибридную архитектуру**:
- объектная модель Unity (`GameObject`, `MonoBehaviour`, `Rigidbody2D`, настройка сцен и префабов)
- кастомный ECS для игрового состояния и последовательности систем (`EcsWorld`, `EcsEntity`, системы)

### Почему выбран этот стиль
- Упрощает интеграцию с Unity (инспектор, префабы, редактирование сцен).
- Дает ECS-разделение поведения (ввод, движение, бой).
- Позволяет мигрировать с legacy-скриптов постепенно, без полного переписывания.

См. [Компоненты ECS](../models/ecs-components.md) для владения состоянием и [Поток боя игрока](../flows/player-combat-flow.md) для конкретного рантайм-поведения.

## Ключевые рантайм-модули
- **Bootstrap:** `EcsCombatBootstrap` создает мир, регистрирует системы, создает сущность игрока.
- **ECS Core:** интерфейсы и инфраструктура мира/сущностей/компонентов и планировщик систем.
- **Игровые системы:** ввод, прицеливание, движение, визуал оружия, стрельба, движение/жизненный цикл снарядов.
- **Legacy-помощники:** следование камеры и выбор направления анимации остаются на MonoBehaviour.

## Известные риски и технический долг
- **Риск wiring сцены:** `EcsCombatBootstrap` пока не подтвержден как подключенный в активных сценах.
- **Связность с глобальными API Unity:** системы напрямую вызывают `Camera.main`, `Input.*`, `Time.time`.
- **Связность по порядку:** поведение зависит от ручного порядка регистрации систем.
- **Точка лишних аллокаций:** буфер выстрелов в `WeaponShootSystem` выделяется каждый кадр.
- **Пробел коллизий:** снаряды двигаются через transform, без пайплайна столкновений/попаданий.

Варианты снижения рисков см. в [Стратегия тестирования](../testing/testing-strategy.md) и [Обработка ошибок](../errors/error-handling.md).
